# Skill authoring

Follow SOUL and the current host directive. This skill grants no extra permissions, model changes or delegation. Use the current model and proportionate evidence.

Use the current request, current conversation and explicitly authorized evidence. Never mine other chats. Find the existing owner before adding a new skill. Define trigger, exclusions, observable result and failure boundaries. Prefer executable checks over prose when they enforce a rule more reliably. Keep host-owned memory, model selection and permissions intact.

## Completion

Write compact instructions and load examples only for concrete ambiguity. Test triggering, non-triggering and failure scenarios. Preserve uncertainty and provenance; do not generalize a single anecdote into a universal rule. Editing a skill or globalizing memory needs scope authority, not inferred permission.

Read [worked cases](references/cases.md) only when the decision or failure boundary is unclear. Do not load unrelated specialists or repeat completed checks without new evidence.
