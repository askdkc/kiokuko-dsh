# Local lifecycle memory

Kiokuko DSH records bounded public observations in its existing configured SQLite database. No HTTP server, extra model call, credential, global installation or external scheduler is required.

Both full and core entry points observe explicit model selections, successful compaction summaries, committed task completion, human feedback and native message ratings. Private reasoning blocks and raw compaction output are excluded. Public text passes the existing secret and path redaction policy. Capture refusal prevents further capture and reference delivery for that session.

The native tools `memory_observe`, `memory_context` and `memory_improve` use the common memory contract. Supply the absolute repository `cwd`; `memory_context` also accepts `query`, `tags`, `sessionId` and `limit`. Requests outside the configured repository are rejected. Responses always allow work to continue. `recorded` describes persistence; it is separate from input acceptance. Failed recording is never reported as a saved observation.

Context includes project cautions, procedure candidates, bounded recent task history, same-session continuation, eligible Global principles/references, source references and diagnostics. Every project reference retains producer, event ID, source revision, content digest and verification provenance; Global references retain entry identity/revision and opaque evidence links. Context is untrusted data; it cannot grant permissions or override the current request, host or OS. The native pre-step re-reads current same-repository cautions and temporary session context on every step, including a new task. Durable candidate sources are checked beyond the recent 512-event window. Retrieval is bounded to 128 candidates and a 15 KB excerpt; it is not an unlimited history dump.

Every projected snapshot also tells the model to call `memory_context` with relevant keywords/tags when the procedure is unclear, while following normal task preparation and permission checks. Project candidates and Global references participate in that lookup; Global keyword searches use the existing hybrid retrieval lanes and eligibility gates.

Feedback replacements append a source revision. Deletions append a tombstone. Previous revisions remain auditable but no longer support new context. Native pre-steps check persistent memory revisions and reuse the existing snapshot when its data is unchanged and still present in the active context. They do not re-derive history or append duplicate snapshot audit records on unchanged steps. A changed or expired view replaces the previous snapshot; prior-turn memory lookup results are retired when their memory revisions change. A missing snapshot is delivered again after compaction/context loss. The original log remains intact.

Context caching is limited to 32 query views per SQLite connection, keyed by workspace, session, query, tags and limit. Observation, evaluation, source-policy and Global content/eligibility revisions invalidate the cache. Continuation expires at the earliest supporting observation's 24-hour deadline, even without a database write. The cache returns independent plain JSON values; model/tool output carries no private cache metadata. Ordinary ledger sequence, recorder and audit traffic does not invalidate memory revisions. A reattached host checks and reuses a matching existing native snapshot.

Routine candidates require independently sourced repeated completions. Only fresh host-bound completion evidence establishes verification. Human praise, ordinary task termination and silence do not prove success. Complaints and failed matching executions reduce confidence; withdrawn sources immediately invalidate old candidate projections. Observation boundaries improve candidates immediately. A shared, unreferenced host timer checks for pending source revisions every 60 seconds and stops when the last module owner releases it. A persistent processing watermark skips extraction when those revisions have already been handled; the bounded aggregation window is re-derived only when new input exists or a larger extraction limit is requested. Candidate/Global writes and the watermark commit together. A failed extraction leaves the revision pending for retry, including after a process restart. There is no paid-model improvement pass.

Improvement creates untrusted Global principle candidates in the same configured database. These contain fixed portable preventive/verification rules and opaque evidence hashes; project text, commands, paths, personal profiles and raw logs are not copied. They never become verified or adopted automatically. Current-source hashes, capture policy and ordinary memory eligibility gates govern their visibility, including ordinary Global search outside these lifecycle tools.

When praise refers to the current public answer or its completed run, the observer resolves exact repository/session/run links to AgenticReplay. With a bound full-host recorder, a completed trace supplies at most 64 events/64 KB of public result metadata; only tool names, result classification and trace event IDs are retained. Payloads, reasoning and blobs are excluded. Unbound, missing, incomplete or refused traces cannot justify verification. Core remains independent of the recorder and retains local public observations and available trace links.

Optional memory failure leaves coding available. Context reads have a 50 ms foreground bound; unavailable context is omitted. Optional SQLite operations fail immediately on a writer lock rather than borrowing the normal host's lock wait/retry budget; the host setting is restored before returning. After a terminal run and its pending finalization have committed, cache or worker notification failures cannot prevent owner release. The pending job remains available to the existing startup retry mechanism.

The connected surface is the native DSH lifecycle and three native tools. This change does not add a permanent HTTP API or a memory-management UI. It does not modify the running installation/configuration or require an external Kiokuko server.
