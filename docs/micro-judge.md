# Native finite-domain micro judge

The experimental `crates/micro-judge` program propagates finite domains and uses minimum-remaining-values search. It has no host callbacks, filesystem effects, network access, permissions or task authority. It is a dependency-free, typed and bounded adaptation of the supplied `prolog/solver.rs` reference algorithm, not the earlier five-way enum router. The reference file's original byte hash is not a hash of this adaptation.

`src/dsh/decisions/intent-assessment.ts` independently submits the original request/context and the candidate to the selected real `DecisionService` under `intent-semantic-match`. It asks about action, reference, constraints and the latest applicable native answer. It never copies the extraction result as a semantic verdict. The configured provider still has to be available; scripted tests prove orchestration, not live model accuracy.

The host builds a typed relation graph over exact message identities/digests, current task/Goal revisions, candidate proposal-set membership, proposal revisions/digests, legal current task operation membership and the independent semantic observation. Strings are interned to opaque integer identities. Boolean unknown has domain `[0,1]`; integer values cannot stand in for Boolean values. Intermediate variables link the relations, so the executable performs propagation and MRV search. These observations cannot grant execution. Existing native ownership, lease, revision, scope, permission, cancellation and admission checks remain required.

A complete entailed relation graph can pass the advisory comparison. Contradiction, ambiguity or inconsistency asks a native clarification. A matching actual UI answer is validated against the same agent/session/question and unchanged context, becomes a fresh native user message/source identity, and is reinterpreted. Its exact text labels the latest explicit revision and its scope; unrelated constraints remain applicable. Wrong-question, replaced/stale context, cancellation and repeat replies cannot create new source authority. Ordinary explanatory answers and native evidence gathering bypass this execution assessment. It operates on resolved candidates; unknown optional intake metadata cannot become a new execution prerequisite. Explicit `typedDecisions.mode=off` retains the pre-existing native authority path and records `assessment_disabled`/`not_run`, with no solver verdict or new grant. An enabled assessment that is unavailable is never converted into that disabled state or a successful comparison. Unowned ordinary native tools keep the existing native-policy path; this assessment currently applies to prepared/owned request intent, not arbitrary shell effects or a new command parser.

Unavailable provider/artifact, timeout, malformed or mismatched output and incomplete/resource-limited search produce `assessment_unavailable`; no successful comparison or execution grant is inferred. Infrastructure failure is reported, not presented as a semantic question that a human answer could repair. Semantic-match and detector events share the existing intake diagnostic lineage and record bounded input/output digests, executable hash, version, duration, completeness, verdict or finite unavailable reason. Raw request/answer text is not copied into diagnostics.

## Protocol and bounds

One UTF-8 line: `kiokuko-fd-v1<TAB>inputIdHex<TAB>sha256PayloadHex<TAB>payload<LF>`. The payload is `workBudget variableCount constraintCount`, then each typed domain (`b|i length values...`), prefix constraints and one Boolean prefix query. Operators are `eq ne lt and or implies diag`; `@0` refers to a variable; Boolean constants are `true false`. `diag a b d` means `abs(a-b) != d`.

Bounds: 128 KiB input, 128 variables, 32 values/domain, 256 constraints, three variables/constraint, 2048 AST nodes, depth 32, two million work steps, 100000 solutions. The host normally requests 200000 work steps, enforces a 1500 ms external deadline and 16 KiB output ceiling, and checks version, input identity/digest, binary hash and result invariants. `complete=false` always means no proof. RSS is explicitly unavailable (`null`) on this portable protocol; Linux `/proc` data is not invented on macOS.

## Native build and delivery

`node scripts/build-micro-judge.mjs /absolute/path/to/rustc` performs an explicit offline build matching the current compiler/host target. It never downloads Rust or modifies shell settings. A matching linker, SDK and target standard library must already exist. The artifact manifest records its SHA256 and byte count with `nativeVerified=false` until native acceptance evidence exists. Normal package build verifies bundled artifacts without compiling or downloading anything. The crate and explicit offline build script remain repository sources; the runtime package contains the prebuilt executable and its verification receipt. Runtime executes only the package's matching, verified artifact path, never PATH or a fallback binary. Unsupported/missing platforms are explicit unavailable; an Apple Silicon run proves no Linux, Intel Mac or Windows execution.

The bundled artifact currently has native acceptance on Apple Silicon macOS only. The native-verification receipt pins its binary/source digests and evidence log digests; it makes no live-model accuracy claim. Run `KIOKUKO_REQUIRE_MICRO_JUDGE=1 node scripts/run-tests.mjs tests/dsh/integration/micro-judge.test.ts` to require actual subprocess execution, all four complete statuses, resource exhaustion, queens counts and host relation tests. Native full-host clarification, live selected provider, corrupted-binary sensitivity, packed artifact host and modular delivery acceptance must also be collected before shipping. A passing connection-only suite must never be reported as that acceptance.


### Native CI artifacts and distribution

The supported build catalog is GNU Linux x64/arm64 and macOS Intel/Apple Silicon. CI uses four native runners (`ubuntu-24.04`, `ubuntu-24.04-arm`, `macos-15-intel`, `macos-15`) and the official Rust 1.85.0 minimal toolchain on those disposable runners. No compiler is installed on a user's machine by these scripts. Linux GNU artifacts require a compatible glibc environment; musl and Windows have no claimed artifact.

`node scripts/build-verify-micro-judge.mjs /absolute/path/to/rustc --output=/new/artifact-directory` compiles on its actual host, runs all 18 mandatory native acceptance cases (including the independent 200-case oracle), rejects skipped/incomplete runs, binds the observed TAP output and compiler/source/binary hashes, then exports one verified target. A failed test leaves the candidate unverified. The transport collector `node scripts/merge-micro-judge-artifacts.mjs /downloaded/artifact-parent` requires all four distinct targets and validates their current source, architecture, bytes, receipts and acceptance log before assembling the package bundle. Missing, duplicate or stale artifacts fail; unsupported execution never becomes success.

Every CI consumer that executes the detector or packages depends on the four native jobs and assembles their results before dependency `prepare` runs. The required aggregate includes native artifact and browser results. `verify-main` retains the tested multi-platform `.tgz` as a release review candidate; it does not publish or install it. The checked-in development artifact may cover only the locally verified host. A local Apple Silicon run establishes only that host's acceptance; new Linux/Intel acceptance requires the corresponding CI job to execute.

Synthetic native workflow and Web approval tests configure a separate scripted decision provider from their known original fixture sources. Wrong actions are contradicted and unknown sources stay insufficient/unavailable. They still execute the packaged Rust detector and native approval/ownership paths; they make no live model accuracy claim. Provider-disabled and provider/artifact-unavailable tests remain separate negative cases.
