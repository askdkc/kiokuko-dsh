# DSH execution support / 対話を継続する作業支援

対応するDSHは `0.1.2-rc.1`。この機能はKiokukoの任意の補助状態として動作し、モデル呼び出しや独立した承認画面を追加しません。Ennoの必須検証、改訂番号、WorkUnitの実行権限、receipt、outbox、最終回答の境界は従来の処理が管理します。

## 作業条件の指定

最初の依頼、または続行の指示に次のように記述します。パスはその依頼を受けた作業ディレクトリからの相対パス、または絶対パスです。

```text
資料を調査し、docs/report.md に根拠付きの報告を作成してください。
探索対象: src, docs
変更対象: docs
変更禁止: docs/archive
制約: 不明な点を推測で埋めない
完了条件:
- 参照した資料と未確認箇所を示す
- 日本語で最終結果を報告する
```

対応するラベルは次のとおりです。

| 条件 | ラベル | ホストによる強制範囲 |
| --- | --- | --- |
| 読み取り範囲 | `探索対象`、`読み取り対象`、`read paths` | 対応ツールの対象パス |
| 変更範囲 | `変更対象`、`変更可能`、`write paths` | 対応ツールの対象パス |
| 変更禁止 | `変更禁止`、`excluded paths` | 書き込み対象パス。読み取り禁止にはしない |
| その他の条件 | `制約`、`constraints` | モデルへの再提示 |
| 完了条件 | `完了条件`、`done when` | モデルへの再提示と結果報告。既存の必須検証は維持 |

パス指定はリテラルです。glob式や自然文の「src以外は変更しない」を新しい機械制約へ自動変換しません。引用行、コードブロック、インデントされた例からも強制条件を作りません。添付ファイルの内容をこの抽出器へ読み込むことはありません。原文と出典のダイジェストを保持し、再提示が長くなる場合は表示だけを短縮します。強制対象のパス条件を黙って間引くことはありません。

同じラベルを後の人間の入力で明示し直すと、その条件を更新します。単なる「続行」では消えません。自然文の解釈候補は、Oduno/Zenkiが任意の `executionHints` として提出できます。

```json
{
  "executionHints": [
    { "field": "constraints", "text": "未確認箇所を明記する", "quote": "根拠付きの報告" }
  ]
}
```

`quote` は実際のユーザー入力に含まれる必要があります。それだけでは承認済みになりません。既存の計画確認で出典とともに表示し、表示した候補と一致する承認だけを適用します。モデルがIDや改訂番号を指定して承認を作ることはできません。無効な候補は無視し、正当なフェーズ提出を再試行させません。承認した解釈が明示されたパス範囲を暗黙に広げることもありません。

## 操作ガードと再提示

対応する構造化ツールは `read`、`read_image`、`glob`、`grep`、`write`、`edit`、および `str_replace_editor` の `view/create/str_replace/insert/undo_edit` です。探索ツールの省略されたパスは作業ディレクトリです。パスの祖先も解決するため、新規ファイルをシンボリックリンク経由で範囲外へ作る操作も拒否します。

拒否は当該ツールの通常のエラー結果です。報告・質問回答・取消・記憶保存をこのガードで拒否しません。既存のEnnoのフェーズやleaseの検証は別に適用されます。既知の条件を復元できない場合は、その条件に依存する操作を保留し、会話と復旧入力を受け付けます。

これはOSのサンドボックスではありません。任意Shell、未対応ツール、別のファイルシステムを持つ外部サービス、呼び出し後の外部変更を完全に制御する機能ではありません。検索の指定パスを検査するもので、外部サービスの検索実装全体を仲介するものでもありません。

作業条件はDSHの動的コンテキストへ投影します。固定Skillとは別に扱い、同じ要求には一つの領域だけを置きます。DSHではコンテキスト組み立ての後にintakeが行われるため、最初の入力・修正入力についても、モデル要求を始める前に同じsnapshotを更新します。原文に含まれる `{{...}}` はテンプレートとして評価しません。

## 反復、停止、再開

同じ検索・読み取りと同じ結果を3回観測すると、次の要求で軌道修正を一度提示します。その提示後に開始された操作が同じ結果を繰り返した場合、入力を消費しないステップ境界で一時停止します。同時実行された4件を、注意後の再反復とは判定しません。24件ごとの整理要求は助言です。

- 実際の子call IDでPTCを識別し、同じイベントの再配送は計数しません。
- ホスト検証、Enno提出、状態確認、記憶保存は計数しません。
- 再検証の実行世代が変わったら、正当な再読を新しく扱います。
- カウンターや提示状態はEnnoの進展ダイジェストに入りません。
- 停止通知をネイティブログへ保存しflushできた場合だけ停止します。失敗時は助言へ縮退します。
- ターン封鎖や成功receiptを作って停止を偽装しません。「提出忘れ」の継続も生成しません。
- 新しいユーザー入力で停止を解除し、条件・承認・検証結果は保持します。別sessionには波及しません。
- 停止中のrunはアンロードで完了・失敗・取消に変換せず、同じsessionとworkspaceから再開します。

## 証拠と最終回答

取得元パス、指定範囲、取得できた行範囲（ネイティブreadが提供する場合）、結果ダイジェスト、call ID、ログ位置、モデル要求への提示状態を別々に記録します。結果ダイジェストは取得した結果の版であり、ファイル全体の版を保証するものではありません。

`full` は観測したツール結果全体が要求へ提示された状態、`partial` は省略を検出した状態、`unknown` は判定できない状態です。指定した一部範囲がfullでも、文書全体を読んだことにはなりません。エラー結果を提示した場合も、取得の成功とは別に記録します。PTCの子結果が要求内に存在しなければunknownです。

observer、キャッシュ、証拠集計の失敗は成功したツール結果を上書きしません。明示された完了条件の不足は作業中に扱い、未確認なら未確認と報告します。terminal後は追加の読み取りや検証を始めません。通常の最終回答を維持し、空回答・通信失敗の場合の既存のホスト報告には、保存できた補助証拠も添えます。補助証拠の読込に失敗してもホスト報告を出します。

長文入力から作る補助検索文字列は、検索APIのUTF-8バイト上限に収めます。ユーザー入力、task、出典を切り詰める処理ではありません。任意の入力投影が失敗した場合も、ネイティブ側の次の操作を一度だけ呼び出します。

## 保存と検証

マイグレーション006は `dsh_execution_frames`、`dsh_exploration_states`、`dsh_execution_evidence` を追加します。過去のマイグレーションと既存receipt/outbox/完了境界は変更しません。旧提出に追加フィールドは不要です。

```sh
npm run typecheck
# DSH_BIN と KIOKUKO_DSH_PACKAGE_ROOT は検証用に用意した対応版の場所を指定する。
KIOKUKO_REQUIRE_DSH_NATIVE=1 npm test
KIOKUKO_REQUIRE_DSH_CLI=1 KIOKUKO_EXPECTED_DSH_VERSION=0.1.2-rc.1 npm run test:e2e:dsh
npm run test:sampledb
npm run publint
npm run pack:check
```

追加の試験は `execution-support.test.ts`、`execution-support-loop.test.ts`、既存のnative agent loop、composition、completion report、migrationの試験に含まれます。実DSHループでは決定的なモデル応答を使い、調査・文章作成は実際のDSHファイルツールとローカルFSを通します。終了期限を超えた場合はrun、turn、receipt、job、停止状態を出力します。単なる例外の有無ではなく、入力、次の操作、最終回答まで検査します。

実ランタイムの回帰試験と、実モデルの能力比較は別です。回帰試験の成功だけで能力向上を実証したとは扱いません。計画にある「前案の5課題」は課題文と採点条件がこの実装依頼に含まれていないため、比較結果は未確定です。比較時は同一課題・モデル・ツール・初期リポジトリ・乱数/推論設定で、変更前後それぞれの成功率、範囲逸脱、重複探索、不要な質問、対話中断、可視最終回答を記録します。逸脱・反復が減っても成功率や継続性が悪化した場合は受入不可です。
