# Diff レビュー

DSH の右ペインの Start から「Diff レビュー」を開きます。会話ヘッダーのボタンからも開けます。選択中のセッションと、そのセッションの作業ディレクトリに結び付いたリポジトリだけを読みます。開いただけではモデルを呼びません。

1. 「未コミット全体」「ステージ済み」「未ステージ」「このターン」から比較対象を選び、「差分を取得」を押します。未追跡ファイルは明示的にチェックしたものだけを含めます。
2. 取得済みの Diff と除外理由を確認し、分析するファイル、モデル、必要ならレビューの目的を選びます。
3. 「分析する」を押すと、選択した provider/model に取得済みの差分と限定した Kiokuko 文脈を送ります。ツール実行やファイル修正はしません。
4. 解説の「根拠」から取得済み snapshot 内の該当 Diff に移動できます。Markdown または JSON で保存できます。

ステージ済みと未ステージの変更は別レイヤーで表示します。ターン差分は DSH が保持している記録を使い、記録が失われた場合は現在の差分で補いません。メモリやモデルが使えないときも取得済みの Diff は表示します。モデルの解説と実行証拠は別の項目で表示し、過去の成功記録が今回の差分に一致するとは推定しません。

`.env`、鍵、認証設定、既知の秘密を含むファイル、バイナリ、symlink、submodule などはテキスト分析から除きます。除外は完全な秘密検出を保証しません。送信前にファイル一覧を確認してください。競合中のファイルがある場合は分析を停止します。

結果はサーバーのメモリ内に既定で 30 分保持します。再起動後や期限切れ時は差分を取得し直してください。比較対象の取得後に作業ツリーが変わると「鮮度: stale」と表示します。分析と表示は保存した snapshot に基づきます。

`diffReview` 設定で `enabled`、`maxFiles`、`maxFileBytes`、`maxSnapshotBytes`、`maxInputBytes`、`maxChunks`、`maxOutputTokens`、`deadlineMs`、`timeoutMs`、`maxCacheBytes`、`ttlMs` を変更できます。既定値は順に `true`、200 件、256 KiB、2 MiB、32 KiB、4、2048、120 秒、15 秒、32 MiB、30 分です。不正な値は起動時に拒否されます。
