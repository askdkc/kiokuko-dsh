# 作業後の自動記憶

通常の Lisp 作業は `lisp_eval` などの公開ツールから進める。作業の開始・完了に、記憶の準備、Goal 登録、記憶適用レビューは不要。DSH の権限、選択した実行経路、Stop、明示的な保護ワークフローはそのまま適用する。

1. native turn が終わると、ホストがそのターンの依頼・ツール結果・最終応答を収集する。
2. その時点のモデルを `purpose: compaction`、ツールなしで呼び、要約・タグ・キーワード・根拠付きの再利用候補を作る。
3. `repositoryLearning.mode: automatic`（既定）では、リポジトリに紐付く SQLite に保存する。質問機能は不要。新しいターンは保存を待たず、完了済みターンの保存も新しい入力だけでは取り消さない。
4. 次の依頼では、最後に保存が完了した投影からタグ・キーワード・内容で候補を絞る。利用可能な Akinator が適用可否を選別する。判定は300msで打ち切り、障害や未設定ならキーワード候補を参考情報として渡す。記憶は権限にも検証済みの事実にもならない。

`repositoryLearning.mode: review` は従来の内容確認後の保存、`off` はこの自動収集・配信を停止する。保存拒否、Stop、忘却・reset、別リポジトリとの分離は維持する。有用な候補がない場合、モデルが応答しない場合、根拠外の参照や秘密情報が含まれる場合は保存しない。失敗・中断を成功に書き換えない。

保存履歴と配信する投影は別。配信する投影には直近12件の観察と20件の仮説という既存の上限があり、全履歴を毎回投入しない。モデル生成と実行結果を区別し、過去の記憶は現在のソースで確かめる。

## 今回の停止原因

提供されたセッションでは `prepare_requested_work` が3回、`profile hint must be a bounded non-empty string` で失敗した。Akinator が改行を含む依頼文を対象の回答として返せる一方、ホストの profile 検証と run 保存が一行しか受け付けなかった。対象はパスだけでなく自然言語の説明でもあるため、両境界で改行を受け付け、元の依頼と除外条件を維持する。

別の停止要因として、次のモデル呼び出しが前の記憶整理の完了を待っていた。通常の呼び出しは保存済みの投影だけを読み、バックグラウンドのモデル生成・確認・保存を待たない。

検証中には、Lispのテスト結果の参照先が常に標準エラー出力を優先し、警告があると結果本文ではなく警告だけを表示する不具合も確認した。テスト結果は標準出力の本文を優先し、本文がなければ標準エラー出力を参照する。保存済みの結果と両方の出力は保持する。

## 長い計画と再開

依頼本文と同じセッションの計画は、長さを理由に捨てない。`read_request_source` は原文の識別子・digest・offset に結び付くページを返し、最後のページでは `nextOffset: null` を返す。モデルへの履歴投影では16,384文字を超える原文を参照とプレビューに置き換え、ネイティブ履歴やSQLiteの原文は変更しない。compaction後も元の計画イベントを参照する。プレビューや記憶の要約だけを完全な実行計画と扱わず、要件・除外条件・受入テストを読み、既存の作業項目へ分割して進める。

`allowedOps` と `stateEligibleOps` は状態だけの候補。モデル向けの `callerEligibleOps` は終了済みrunのresumeを除外する。モデルが実行を試みると `EXPLICIT_USER_RESUME_REQUIRED` と具体的な人間のコマンドを返す。モデル引数での `explicit=true` は受け付けない。

明示resumeの応答は新しいrevision/generationと `preparationRequired`、理由 `task_state_changed`、必要な参照を含む。同じ依頼・対象・所有者・スコープの確定済み継続だけを新しい参照で再検証し、その後も通常の準備と実行権限確認を通る。unknown、scope_change、Stop、所有者変更、古い参照は継承しない。`task_completion status` は従来どおりreceipt保存を伴い、読み取り専用の例外にはしていない。

実行計画の処理能力には利用モデル、メモリ、ディスクの物理的な上限がある。長文を一回のモデル入力へ押し込むことや、全項目の完了を無検証で保証する設計ではない。原文の保持、ページ参照、作業分割、未完了項目の引き継ぎで処理する。

## リポジトリ紐付けと通常の編集

`.kiokuko.json` と保存済みのリポジトリIDが衝突した場合、どちらかへ自動で紐付け直したり、別IDの記憶を利用したりしない。記憶の参照は保留し、実行所有者・Stopの確認に必要なデータベースは維持する。`prepare_requested_work` は記憶の紐付けに限った失敗と、通常の作業を続ける案内を返す。

既存タスクに所有されていない通常の `write`／`edit` は、読み取りと同様にネイティブ権限で動く。任意の準備に失敗しても、その権限を取り消さない。PTCの内部呼び出しは実行中の親トークンに結び付け、各ツールの権限・引数・所有者を再検証する。タスク専用ツール、別セッション、明示的な拒否、Stopは免除しない。

`native-edit-memory-conflict.test.ts` は、衝突した保存状態から起動し、native／PTC、core／adapterの各経路でファイルを読み、編集し、読み直す。準備失敗後の続行、ネイティブ拒否、Stop、紐付けを変更しないことも検証する。

## 検証対象

`tests/dsh/integration/lisp-memory-completion-native.test.ts` は実際のDSHハーネスとLispランタイムで、JSONファイルの作成・読み直し、compaction、自動保存、プラグイン再読み込み後のキーワード参照を通す。モデルの出力は固定した検証用応答であり、実プロバイダーの判断品質を保証するテストではない。

`repository-learning.test.ts` は保留中の記憶生成が別チャットを止めないこと、保存拒否・停止・reset・再起動の境界を扱う。`repository-learning-retrieval.test.ts` は Akinator の候補除外、障害・タイムアウト時のフォールバック、無関係な記憶の除外を扱う。

`request-plan-native.test.ts` は約100万文字の計画をネイティブ履歴からcompaction後に読み出し、native/PTC、core/adapterで準備からファイル変更までを検証する。`request-sources.test.ts` は数MBの原文をページから完全に再構成する。`task-workflow-host.test.ts` と `task-state.test.ts` は終了状態ごとのモデル拒否、人間の明示resume、新しい準備、旧lease・CAS・operationIdの拒否と再起動後の保持を検証する。モデル出力は試験用であり、実モデルの長文理解の品質評価とは区別する。
