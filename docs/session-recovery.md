# 中断した会話の復旧

Web の会話上部にある **セッション復旧** から操作します。

- **この履歴から続ける**: 保存済み履歴を保ったまま、状態確認を求める新しい依頼を一度だけ送信します。保存されたモデル接続が利用できる必要があります。
- **空の会話でやり直す**: 同じ作業場所とプリセットで新しい会話を作成します。元のユーザー依頼を時系列で入力欄に引き継ぎ、確認後に送信します。元のモデル接続が失われていても作成できます。必要なら送信前にモデルを選択してください。

元の履歴は削除・書き換えしません。実行中の会話では復旧操作を停止します。新規作成は元の実行環境を再開せず、保存履歴から行います。応答が届かなかった操作の再送では同じ復旧操作 ID を使い、二重作成・二重送信を防ぎます。

CLI では対象の会話を開いて、以下を入力します。

```text
/kioku-recover status
/kioku-recover continue
/kioku-recover new
```

`new` は作成した会話の `/resume ID` と引き継ぐ依頼文を表示します。まだモデルには送信しません。元の会話を開けない場合は Web の保存履歴から操作してください。

クラッシュ直前のツール処理は、実際には完了していても結果が保存されていない場合があります。復旧機能はそれを自動再実行せず、結果不明として状態確認をモデルへ指示します。復旧後のモデルによる処理は通常の権限管理に従います。前プロセスのバックグラウンドジョブやジョブ ID は復元できません。新規会話の添付ファイルは再添付してください。長い依頼文を自動転記できない場合はその旨を表示し、内容を黙って切り捨てません。

更新したパッケージを使うにはホストの再起動が必要です。作業中のホストを強制終了せず、実行を終えてから通常の終了・起動を行ってください。
